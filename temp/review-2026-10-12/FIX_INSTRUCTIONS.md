## Что делать

1. Исправить ВСЕ замечания (critical, major, minor) по своим файлам. Номера строк в отчётах могут сдвинуться на 1–2 строки (уже сконвертированы CRLF → LF) — ориентируйся на текст.
2. **Каждую команду, флаг, ключ конфига, API, URL сверяй с первоисточником**: README/исходники через `gh api repos/OWNER/REPO/readme --jq .content | base64 -d`, `gh api repos/OWNER/REPO/contents/PATH`, PyPI (`curl -s https://pypi.org/pypi/PKG/json`), официальная документация (curl/WebFetch), при возможности — `--help` реально установленной утилиты во временном venv (`python3 -m venv /tmp/venv-x`). Для сети запрашивай `full_network`.
3. **Не выдумывай.** Если факт/команду не удалось подтвердить — удали его или замени на ссылку на официальную документацию. Меньше примеров, но рабочих — лучше. Никаких придуманных бенчмарков, цифр, цитат, кейсов, партнёрств, блог-постов. Числа о проекте Ruarxive — только подтверждённые (см. ниже).
4. Для страниц инструментов, которые переписываешь, добавь в конце раздела установки строку вида: `> Команды сверены с README/`--help` версии X.Y.Z (октябрь 2026).` — только если действительно сверял.
5. Если инструмент закрыт/архивирован/заблокирован — так и написать в начале страницы (`:::warning`), предложить живую альтернативу.
6. Ссылки на GitHub и внешние сайты, которые меняешь или добавляешь, проверь (`gh api repos/...` или `curl -sI -L`). Плейсхолдеры-примеры (`example.com`, `PLxxxx`) держи только внутри код-блоков.
7. Frontmatter у каждого своего файла должен быть такого вида (добавь, если нет; `title` — по H1, `description` — 1–2 предложения по-русски, в кавычках):
   ```yaml
   ---
   title: ...
   description: "..."
   last_updated: 2026-10-12
   ---
   ```
   Существующие поля (`sidebar_position`, `sidebar_label`, `slug`, `id`, `keywords`) сохраняй. `last_updated: 2026-10-12` ставь у каждого файла, который ты изменил по существу. Не переименовывай поле в `last_update` — это будет сделано централизованно позже.
8. Стиль: русский язык, без смешения с английскими фразами в прозе, без эмодзи сверх уже принятых в файле, сохраняй структуру разделов страницы, если она осмысленна.

## Ограничения

- Редактируй ТОЛЬКО файлы из своего списка. Не трогай `sidebars.js`, `docusaurus.config.js`, `_category_.json`, файлы других агентов, файлы в `temp/` (кроме своего журнала).
- Не создавай, не удаляй и не переименовывай файлы в `kb/`. Если страница описывает несуществующий инструмент — перепиши её честно (что есть на самом деле), а не удаляй.
- Не запускай `npm run build`/`docusaurus` (параллельные сборки конфликтуют) — сборку сделает координатор.
- **MDX-ловушки** (сломают сборку): вне код-блоков и инлайн-кода не должно быть голых `{`, `}`, `<` перед буквой (`<url>` → `` `<url>` `` или `&lt;url&gt;`), незакрытых HTML-тегов. Число ``` в файле должно быть чётным. Внутренние ссылки — только на существующие страницы (`/kb/...` без `.md`), проверь `ls kb/...`.
- Не меняй git-состояние (никаких commit/stash/checkout).

## Политика по правовым и чувствительным темам

- Персональные данные: с 01.03.2021 действует ст. 10.1 152-ФЗ — для распространения ПДн, разрешённых субъектом для распространения, нужно отдельное согласие; не утверждать, что «общедоступные данные можно без согласия».
- Единый срок реакции на запрос об удалении: «рассматриваем запрос и отвечаем в течение 10 рабочих дней» — использовать везде одинаково (contact: infoculture@infoculture.ru).
- Авторское право: в общественном достоянии — официальные документы госорганов (п. 6 ст. 1259 ГК РФ), а не сайты целиком; упоминать ст. 1275 ГК РФ (свободное использование библиотеками/архивами) с оговоркой об её ограниченности; публичная доступность ≠ разрешение.
- Не утверждать, что за архивацию «не преследуют» или что обход технических ограничений — «серая зона»; писать, что обходить технические средства защиты нельзя, и рекомендовать консультацию юриста.
- **Не рекомендовать и не описывать VPN, Tor, прокси и другие средства обхода блокировок** (запрет популяризации с 01.03.2024). Удалить такие советы, onion-адреса, «зеркала». Допустимо нейтрально: «если ресурс недоступен, используйте другие архивы (archive.today, национальные веб-архивы) или обратитесь к коллегам».
- Не утверждать, что «хостинг вне РФ делает это законным».
- Иноагенты/нежелательные организации: при упоминании СМИ и организаций указывать статус ТОЛЬКО если он подтверждён по официальному источнику (реестры Минюста или новости с датой). Подтверждено: «Медуза» — нежелательная организация с 26.01.2023; телеканал «Дождь» — нежелательная организация с 25.07.2023 (ранее иноагент); Transparency International — нежелательная с марта 2023. Остальные (Free Russia Foundation, IStories, «Новая газета Европа», Bard College, «ОВД-Инфо», «Холод», PEN America и др.) — проверь сам через WebSearch/WebFetch; если подтверждено — укажи статус и дату; если не удалось подтвердить — убери упоминание организации, если оно не необходимо, иначе нейтрально без оценок. Формат пометки: «(признана в РФ нежелательной организацией, ДД.ММ.ГГГГ)» / «(внесён Минюстом РФ в реестр иностранных агентов)».
