# Preflight-чеклист перед архивацией сайта

Прежде чем запустить кроулер — будь то одна статья или сайт из миллиона страниц — полезно пройти короткий чек-лист. Это **снижает риск** пропустить контент, получить бан, нарушить авторские права или обнаружить через месяц, что архив никому не нужен.

> **Принцип:** 1 час подготовки экономит 10 часов на переделку. Для регулярных архивов чек-лист должен стать шаблоном.

## 1. Зачем и для кого

### Сформулируйте цель

Прежде чем скачивать, ответьте на пять вопросов:

- [ ] **Зачем этот сайт нужно сохранить?** Возможные причины: риск закрытия, культурная/историческая ценность, исследовательский запрос, журналистское расследование, требование закона.
- [ ] **Кто основной пользователь архива?** Исследователи, журналисты, общественность, юристы, внутренняя команда.
- [ ] **Когда архив должен быть готов?** Дедлайн часто диктует стратегию.
- [ ] **Где будет жить архив?** Локально и в облачном хранилище (S3 и аналоги), публично (Internet Archive), на собственном сервере воспроизведения (pywb).
- [ ] **Какой уровень полноты нужен?** Только главная страница, только статьи, всё включая админку.

### Пример хорошей постановки задачи

```
Цель: сохранить архив ежедневных отчётов правительственного сайта X за период 2018–2026.
Пользователь: исследователи прозрачности государственных закупок.
Срок: к Q2 2027 собрать всё за 2018–2025; регулярно (ежемесячно) — 2026.
Хранилище: S3 Standard в РФ + копия на R2 для публичного доступа.
Полнота: все страницы отчётов + прикреплённые PDF + связанные документы.
```

Не годятся цели вроде «просто сохранить», «на всякий случай», «пока не закрыли». У каждого архива должен быть **адресат**.

## 2. Scope — что именно скачивать

### Уровни глубины

| Уровень | Что скачиваем | Когда использовать |
|:---|:---|:---|
| **L1 — Single page** | 1 URL | Цитата, разовая страховка |
| **L2 — Section** | Раздел сайта + вложенные 1–2 уровня | Тематическая архивация |
| **L3 — Whole site** | Весь сайт по sitemap, в пределах лимитов | Полная архивация |
| **L4 — Whole domain** | Домен + поддомены | Организация, портал |
| **L5 — Time series** | L3 или L4, регулярно по расписанию | Динамический контент |

### Что включить и исключить

Зафиксируйте в `seeds.csv` или `seeds.txt`:

```csv
url,include_regex,exclude_regex,max_depth,priority
https://example.com/,.*,\.json$,5,high
https://example.com/news/.*,.*,\?preview=.*,10,high
https://example.com/admin/,❌,❌,0,none
```

**Include** — что хотим собрать:

- Основные разделы.
- Архивы (например, `/2024/`, `/archive/`).
- API-эндпойнты для статического контента.

**Exclude** — что НЕ собирать:

- Админка и личные кабинеты (`/admin/`, `/user/`).
- Динамические превью (`?preview=*`, `?draft=*`).
- Логи запросов.
- Ленты обновлений (RT-уведомления), которые могут вызвать зацикливание.

### Размер и лимиты

Зафиксируйте:

- **Максимум страниц:** 1000 / 10 000 / 100 000 / без лимита.
- **Максимум байт:** 1 ГБ / 10 ГБ / 100 ГБ.
- **Максимум длительности:** 1 час / 1 день / 1 неделя.
- **Что делать при превышении:** остановить / продолжить с предупреждением / собрать только high-priority.

## 3. Инструменты и режимы

### Выбор инструмента

| Сценарий | Инструмент | Почему |
|:---|:---|:---|
| Статический сайт без JS | [wget](/kb/guides/wget) | Простота, запись WARC |
| Сайт на WordPress | ⭐ [wparc](https://github.com/ruarxive/wparc) | Чистые данные через WP REST API |
| Современный сайт на JS | [Browsertrix](/kb/instruments/tools/browsertrix) | Полная отрисовка |
| Браузерная сессия, требуется логин | [Browsertrix](/kb/instruments/tools/browsertrix) + профиль | Сохраняет cookies |
| Telegram-канал | ⭐ [tgarc](https://github.com/ruarxive/tgarc) | API + метаданные |
| Видео | [yt-dlp](/kb/instruments/tools/yt-dlp) | Лучшее качество, метаданные |
| Большой сайт, очередь | [Heritrix](/kb/instruments/tools/heritrix) | Стандарт Internet Archive |
| Кураторский отбор с согласованием | [Web Curator Tool](/kb/instruments/tools/web-curator-tool) | Процесс с отбором и проверкой |

### Поведения (behaviors) для JS-сайтов

В Browsertrix Crawler поведения задаются параметром `--behaviors`; по умолчанию включены `autoplay`, `autofetch`, `autoscroll` и `siteSpecific`:

- ✅ `autoscroll` — прокрутка страницы, пока подгружаются новые элементы.
- ✅ `autoplay` — запуск видео и аудио на странице.
- ✅ `autofetch` — загрузка ресурсов, которые браузер мог не запросить сам (другие разрешения изображений в `srcset`, ленивая загрузка и т. п.).
- ✅ `siteSpecific` — готовые сценарии для отдельных соцсетей (YouTube, Twitter/X, Instagram, Telegram и др.).
- ⚠️ `autoclick` — клики по ссылкам и кнопкам без перехода со страницы; включайте осторожно.
- 📝 Собственные поведения — пользовательские скрипты (см. [документацию Browsertrix Crawler](https://crawler.docs.browsertrix.com/user-guide/behaviors/)).

### Учётные записи и аутентификация

Если нужные страницы доступны только после входа и у вас есть **законный** доступ к ним:

1. **Используйте отдельную учётную запись** архивиста, а не основной личный аккаунт.
2. **Создайте профиль браузера** командой `create-login-profile` Browsertrix Crawler: вход выполняется вручную в окне браузера, профиль сохраняется в файл `.tar.gz`.
3. **Передайте профиль краулеру** параметром `--profile`.

:::warning
Не используйте чужие учётные записи и cookie-файлы и не обходите авторизацию. Не публикуйте файлы профилей: в них хранятся данные для входа. Архивация закрытой части сайта требует отдельной правовой оценки — см. [Условия использования сервисов](/kb/legal/terms-of-service).
:::

## 4. Юридические ограничения

### Что проверить

- [ ] **Авторские права.** Кто владеет контентом сайта? Даже на сайте госоргана авторским правом не охраняются только официальные документы (законы, судебные решения, иные официальные материалы) и сообщения о фактах (п. 6 ст. 1259 ГК РФ); статьи, фотографии и оформление охраняются. Подробнее: [Авторское право](/kb/legal/copyright).
- [ ] **Персональные данные.** Есть ли на сайте пользовательский контент (комментарии, отзывы)? Подробнее: [Персональные данные](/kb/legal/personal-data).
- [ ] **Условия использования (ToS).** Что говорит `robots.txt` и правила сайта про автоматический сбор? Подробнее: [Условия использования](/kb/legal/terms-of-service).
- [ ] **Статус ресурса.** Не признан ли владелец ресурса нежелательной организацией, нет ли материалов, признанных экстремистскими? За их распространение предусмотрена ответственность.
- [ ] **Доступность.** Если ресурс недоступен, используйте другие архивы (archive.today, национальные веб-архивы) или обратитесь к коллегам.
- [ ] **Логин.** Закрытая часть сайта требует отдельной правовой оценки; обход авторизации и технических ограничений недопустим.

### Когда разрешение обычно не требуется

- **Официальные документы** и сообщения о фактах (п. 6 ст. 1259 ГК РФ).
- **Материалы под открытыми лицензиями** (CC BY, CC0, MIT и т. п.) — в рамках условий лицензии.
- **Собственный сайт** архивиста.

Срочность (угроза закрытия сайта) сама по себе не даёт правового основания для публикации чужих материалов: сохранить копию и опубликовать её — разные действия.

### Когда нужно разрешение или отдельное основание

- **Публикация архива** с чужими произведениями (статьи, фото, видео).
- **Закрытый контент** (платный, личный кабинет).
- **Партнёрство с редакцией** СМИ — договор о передаче материалов.

## 5. Расписание

| Тип расписания | Когда использовать | Пример |
|:---|:---|:---|
| Однократно | Разовое сохранение | Ручной запуск скрипта сбора |
| Регулярно (cron) | Еженедельно/ежемесячно | `0 2 * * 0 /opt/archive/archive-weekly.sh` |
| По событию | Изменился sitemap или RSS | Скрипт проверки изменений запускает сбор (см. [Стратегии сбора](/kb/guides/collection-strategies)) |
| Серией | Несколько ресурсов | Серия сборов в течение недели |

### Что фиксировать

- Длительность одного прохода (для мониторинга).
- Интервал между проходами (для оценки нагрузки).
- Кто отвечает за запуск.
- Когда прекратить (например, после явного закрытия сайта).

## 6. Хранилище и публикация

### Перед запуском: куда положить результат?

- [ ] **Локально на диск** — для тестового прогона.
- [ ] **S3 / R2 / Backblaze** — для долгосрочного хранения.
- [ ] **Internet Archive** — для публикации (если у вас есть на это права).
- [ ] **Ruarxive** — для общественно значимых российских ресурсов: сообщите о ресурсе через [запрос на архивацию](/kb/preserved-projects-form) или в [чат](https://t.me/ruarxivechat).
- [ ] **Не сохранять** — если цель прогона — просто проверить качество.

### Структура каталогов

```
archive-name/
├── raw/
│   └── 2026-10-12_browsertrix_run-001/
│       └── archive.wacz
├── logs/
│   └── 2026-10-12_run.log
├── checksums/
│   └── archive.wacz.sha256
└── metadata/
    ├── collection.json  # datapackage.json
    └── README.md
```

## 7. Контакты и коммуникация

### С кем связаться

- [ ] **Владелец сайта** — если есть контакт; предупредить, что идёт архивация.
- [ ] **Юрист / DPO** — если есть персональные данные.
- [ ] **Хостер** — если планируется долгая нагрузка.
- [ ] **Команда Ruarxive** — для сложных или крупных проектов.
- [ ] **Сообщество** — для совместных проектов (Archive Team и т. п.).

### Куда сообщать о ходе

- **Ruarxive** — сообщить о ресурсе через [запрос на архивацию](/kb/preserved-projects-form); уже сохранённое — в [таблице](https://airtable.com/shrO1hise7WgURXg5).
- **Telegram-чат** — если нужны помощники.
- **GitHub** — если используются инструменты Ruarxive (issue).

## 8. Тестовый прогон

Перед полноценным архивированием:

- [ ] **Запустить на 1 странице** и проверить результат в ReplayWeb.page.
- [ ] **Запустить на 5–10 страницах** и оценить скорость, размер, ошибки.
- [ ] **Проверить cookies/логин** если требуется.
- [ ] **Проверить поведения** для JS-сайтов.
- [ ] **Оценить объём**: `du -sh /path/to/archive`.

## 9. Мониторинг во время сбора

| Метрика | Где смотреть | Что должно настораживать |
|:---|:---|:---|
| Скорость (URL/мин) | логи кроулера | Падение ниже 50 % от начальной |
| Объём (ГБ/час) | `du` | Резкий рост (возможно, бесконечный цикл) |
| 4xx / 5xx ответы | логи | > 5 % ответов |
| Капчи / блокировки | логи | Сайт начал блокировать |
| CPU / память | `htop`, `docker stats` | Утечка памяти в кроулере |
| Сеть (Мбит/с) | `nethogs` | Превышение лимита |

## 10. Пост-обработка

После успешного сбора:

- [ ] **Проверить качество** в ReplayWeb.page (3–5 случайных страниц).
- [ ] **Посчитать статистику**: сколько страниц, какой средний размер.
- [ ] **Сохранить логи** для аудита.
- [ ] **Зафиксировать дату** в метаданных.
- [ ] **Создать SHA-256** для каждого WARC/WACZ.
- [ ] **Сообщить в Ruarxive** через форму, если ресурс общественно значим.
- [ ] **Написать в чат**, если нужна помощь с обработкой.

## 11. Резерв и дубликаты

### Правило 3-2-1 (напоминание)

- 3 копии: оригинал + 2 бэкапа.
- 2 разных носителя.
- 1 копия вне офиса / в другом регионе.

### Автоматизация бэкапа

```bash
#!/bin/bash
# backup-archive.sh
SRC=/data/archive-name/raw
DST_S3=s3://my-bucket/archive-name/
DST_IA=archive-name.wacz

# Копирование в S3
aws s3 sync "$SRC" "$DST_S3"

# Загрузка в Internet Archive (только если у вас есть права на публикацию)
ia upload "$DST_IA" "$SRC/latest.wacz" \
  --metadata="mediatype:data" \
  --metadata="title:archive-name, $(date +%Y-%m-%d)"
```

Не указывайте в метаданных лицензию (`licenseurl`) на чужой контент: назначить лицензию может только правообладатель.

## 12. Шаблон `preflight.md`

Скопируйте в директорию архива:

```markdown
# Preflight-чеклист для архивации

## Цель
[краткое описание]

## Scope
- URL: [seeds.txt](seeds.txt)
- Глубина: [L1-L5]
- Лимиты: [X страниц, Y ГБ, Z часов]

## Инструменты
- [инструмент + команда]

## Юридический статус
- Авторские права: [...]
- Персональные данные: [...]
- ToS / robots.txt: [...]

## Расписание
- Старт: [дата]
- Интервал: [раз в неделю]
- Кто отвечает: [@ник]

## Хранилище
- Локально: [...]
- S3 / R2: [...]
- IA / Ruarxive: [...]

## Контакты
- Владелец сайта: [...]
- Куратор: [...]

## Метрики успеха
- [полнота %, объём, срок]
```
