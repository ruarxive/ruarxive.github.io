# MAX

**MAX** — российский мессенджер, продвигаемый через административный ресурс и преподносимый как «государственный». В [публикации #175](https://t.me/ruarxive/175) (декабрь 2025 года) Ruarxive обратил внимание на два свойства MAX, которые принципиально отличают его от Telegram с точки зрения архивации:

1. **Содержимое каналов недоступно без авторизации.** У Telegram есть публичный веб-просмотр каналов (`https://t.me/s/<channel>`), у MAX такого нет. Поисковые системы и [Internet Archive](/kb/similar/internet-archive) собирают только общедоступные по HTTP/HTTPS материалы, поэтому содержимое MAX они не видят и сохранить не могут.
2. **Нет выгрузки данных (data take-out).** В Telegram можно выгрузить свои чаты и каналы через [Telegram Desktop](/kb/instruments/data-take-out/dto-telegram); в MAX не предусмотрен экспорт ни своих чатов, ни своих каналов, ни читаемых каналов.

В итоге MAX — **закрытое, контролируемое и неархивируемое пространство**: даже чтение каналов возможно только после авторизации, в том числе в веб-клиенте.

Проверка 29.10.2026 на открытом канале ведомства (`max.ru/id5500000054_gos`) это подтвердила. Ссылка вида `max.ru/<канал>` без входа показывает только карточку: название, короткое имя и описание. Публикаций на ней нет. Кнопка «Открыть в браузере» ведёт в веб-клиент `web.max.ru`, а он без входа просит отсканировать QR-код или ввести номер телефона.

## Bot API

У MAX есть документированная платформа для разработчиков — [dev.max.ru](https://dev.max.ru/docs): Bot API, библиотеки на JavaScript и Go, мини-приложения. Для архивации важны её ограничения:

- подключиться к платформе (чат-боты, мини-приложения, каналы организаций) могут только юридические лица, ИП и самозанятые — резиденты РФ;
- метод [`GET /messages`](https://dev.max.ru/docs-api/methods/GET/messages) возвращает сообщения или посты из чата или канала, **только если бот в нём администратор**.

То есть Bot API позволяет автору выгрузить посты **собственного** канала, куда он добавил бота-администратора, но не даёт доступа к чужим каналам и не заменяет публичный просмотр.

Также на dev.max.ru упоминается программа Open Client API для разработки альтернативных клиентов (по заявке); возможности её использования для архивации не изучались.

:::warning
Массовое сохранение чужих материалов из MAX возможно только через реверс-инжиниринг клиента, что противоречит условиям использования платформы и не рекомендуется.
:::

## Сравнение с Telegram

| Возможность | Telegram | MAX |
|---|---|---|
| Просмотр канала без авторизации | ✅ `https://t.me/s/<channel>` | ❌ |
| Индексация поисковиками и Internet Archive | ✅ (публичные страницы каналов) | ❌ |
| Выгрузка своих данных | ✅ Telegram Desktop | ❌ |
| Документированный API | ✅ Bot API, MTProto | ⚠️ Bot API (только чаты, где бот — администратор; для организаций и ИП из РФ) |

## Возможные стратегии

:::note
Ни одна из стратегий ниже не реализована в виде готового поддерживаемого инструмента.
:::

### 1. Выгрузка собственного канала через Bot API

Автор канала может добавить своего бота администратором и периодически сохранять посты через `GET /messages`. Это рабочий путь для организаций, которые сами публикуют контент в MAX и хотят сохранить его копию.

### 2. Ручная фиксация «изнутри»

Скриншоты и копирование текста из приложения. Полнота крайне низкая, метаданные теряются.

### 3. Сохранение дублирующих публикаций

Если автор дублирует публикации в Telegram, на своём сайте или в других соцсетях, архивировать можно эти копии. Это неполная стратегия: связь публикации с каналом MAX при этом теряется.

### 4. Продвижение открытости

Совместная работа с экспертным сообществом за открытость государственных и госкорпоративных платформ — аналогично тому, как международные инициативы добиваются сохранения государственных данных (см. [Международные примеры](/kb/case-studies/international-examples)).

## Что делать прямо сейчас

1. **Не использовать MAX как единственную площадку для общественно значимого контента.** Для архивации лучше подходят платформы с открытым веб-доступом.
2. **Предлагать авторам дублировать посты** в открытые Telegram-каналы, на собственные сайты или в соцсети с публичным доступом.
3. **Документировать случаи, когда важный контент публикуется только в MAX**, чтобы сообщество знало о таких пробелах.
