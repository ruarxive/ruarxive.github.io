# MAX

**MAX** — российский мессенджер, продвигаемый через административный ресурс и преподносимый как «государственный». С точки зрения цифровой архивации он отличается от Telegram двумя фундаментальными свойствами:

1. **Содержимое каналов и чатов недоступно без авторизации** — публичные URL вида `https://t.me/s/<channel>` (как в Telegram) отсутствуют. Поисковики и [Internet Archive](/kb/similar/internet-archive) не видят содержимое каналов и не могут его сохранить.
2. **Нет data-take-out (DTO)** — в отличие от Telegram ([Telegram Desktop](/kb/instruments/social-media/instagram) или web-экспорт), ни встроенный экспорт данных в MAX отсутствует, ни публичного/документированного API нет.

В результате MAX — это **закрытое, контролируемое и неархивируемое пространство**: даже чтение постов прошедших авторизацию каналов идёт только под контролем собственной платформы, в том числе в веб-клиенте.

> [!WARNING]
> На октябрь 2026 года в MAX нет архивируемых публичных интерфейсов. Любая попытка массового сохранения материалов сторонними разработчиками требует реверс-инжиниринга клиента и противоречит условиям использования платформы.

## Когда речь заходит об архивации

✅ Подходит для обсуждения в команде Ruarxive, если:

- нужно зафиксировать **риск-профиль** платформы для сообщества;
- требуется объяснить читателям KB, **почему MAX принципиально отличается от Telegram** по архивируемости;
- формулируется политика проекта: «архивируем только то, что доступно через открытые протоколы».

❌ Не подходит:

- для практической архивации каналов MAX штатными средствами — на сегодня таковых нет;
- для сравнения с Telegram при выборе инструмента: MAX технически **не равноценен** Telegram;
- как источник открытых данных — всё содержимое MAX приватно с точки зрения внешнего наблюдателя.

## Что именно недоступно для архивации

| Возможность | Telegram | MAX |
|---|---|---|
| Просмотр канала без авторизации | ✅ `https://t.me/s/<channel>` | ❌ HTTP-эндпоинта нет |
| Индексация поисковиками (Яндекс, Google) | ✅ Частично | ❌ |
| Попадание в Internet Archive | ✅ С 2014 г. | ❌ |
| Data-take-out (экспорт своих данных) | ✅ Telegram Desktop | ❌ |
| Документированный Bot/API | ✅ Bot API, MTProto | ❌ |
| Wayback Machine (web.archive.org) | ✅ Архив с 2014 | ❌ |

## Возможные стратегии

> [!NOTE]
> Все стратегии ниже — гипотетические. На октябрь 2026 года ни одна из них не реализована в виде готового, поддерживаемого инструмента.

### 1. Ручная фиксация «изнутри»

Скриншоты и копирование текста из приложения. Полнота крайне низкая, метаданные теряются, проверяемость нулевая.

### 2. Реверс-инжиниринг клиента

Анализ трафика мобильного/desktop-приложения (MITM через собственное устройство). Юридически серая зона, нарушает ToS, требует постоянной актуализации после каждого обновления клиента.

### 3. Лоббирование открытого API

Совместная работа с экспертным сообществом и правозащитными организациями для продвижения обязательной открытости государственных/госкорпоративных платформ — по аналогии с тем, как это делает [DataRefuge](/kb/case-studies/international-examples) для климатических данных.

### 4. «Слепое зеркало»

Если часть авторов дублирует свои публикации в Telegram или на личных сайтах, архивация источника-дублёра — рабочая, но неполная стратегия. Принадлежность автора к каналу MAX в этом случае утрачивается.

## Что делать прямо сейчас

1. **Не использовать MAX как единственную площадку для контента, имеющего общественную значимость.** Для архивации лучше выбирать платформы с открытыми протоколами.
2. **Стимулировать авторов дублировать посты в открытые каналы Telegram**, на собственные сайты или в социальные сети с публичным DTO.
3. **Документировать случаи, когда важный контент публикуется только в MAX** — чтобы эта информация была доступна сообществу и можно было инициировать переговоры.
