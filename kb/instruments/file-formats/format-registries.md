# Реестры форматов файлов

При долгосрочном цифровом хранении (digital preservation) недостаточно знать расширение файла (например, `.doc`). Один и тот же файл может быть создан разными версиями программного обеспечения, иметь разные особенности структуры и требовать разных инструментов для открытия.

Для точной идентификации форматов используются **реестры форматов** и уникальные идентификаторы.

## Почему не расширения?

Расширения файлов ненадежны:
*   Они могут быть изменены пользователем (переименование `.jpg` в `.png`).
*   Они неоднозначны (`.doc` может быть файлом Word 97, Word 2003 или просто текстовым файлом).
*   Они не дают информации о версиях формата.

## Основные реестры

### PRONOM (The National Archives UK)

[PRONOM](https://www.nationalarchives.gov.uk/PRONOM/) — это онлайн-реестр технических сведений о форматах файлов и программном обеспечении. Он поддерживается Национальным архивом Великобритании и является стандартом де-факто в цифровой архивации.

*   **PUID (PRONOM Unique Identifier)**: Уникальный идентификатор формата в системе PRONOM.
    *   Пример: [`fmt/40`](https://www.nationalarchives.gov.uk/PRONOM/fmt/40) (Microsoft Word Document 97-2003)
    *   Пример: [`x-fmt/111`](https://www.nationalarchives.gov.uk/PRONOM/x-fmt/111) (Plain Text File)

Идентификаторы PUID устойчивы и используются большинством инструментов идентификации (например, DROID, Siegfried). Сигнатуры PRONOM публикуются в виде сигнатурных файлов DROID и регулярно обновляются.

*   **Использование**: Siegfried, FIDO, DROID
*   **Обновления**: Регулярные выпуски сигнатурных файлов
*   **Доступ**: Онлайн-база данных; карточка формата открывается по адресу вида `https://www.nationalarchives.gov.uk/PRONOM/fmt/40`

### Library of Congress Sustainability of Digital Formats (LC FDD)

[Ресурс Библиотеки Конгресса США](https://www.loc.gov/preservation/digital/formats/), описывающий устойчивость цифровых форматов.

*   Предоставляет подробные описания технических характеристик.
*   Оценивает форматы по критериям устойчивости (раскрытость, распространенность, прозрачность, отсутствие патентов и т. д.).
*   Имеет свои идентификаторы, например [`fdd000125`](https://www.loc.gov/preservation/digital/formats/fdd/fdd000125.shtml) для PDF/A-1.

### Wikidata

[Wikidata](https://www.wikidata.org/) становится все более важным хабом для сведений о форматах файлов.

*   Связывает идентификаторы разных систем (PRONOM, LC FDD, MIME-типы).
*   Позволяет делать сложные SPARQL-запросы.
*   Идентификатор сущности (QID), например [Q42332](https://www.wikidata.org/wiki/Q42332) (формат PDF).

### Digipres.org

[Digipres.org](https://www.digipres.org/) — ресурс сообщества цифрового сохранения. Раздел [Formats](https://www.digipres.org/formats/) агрегирует сведения из нескольких реестров (PRONOM, LC FDD, Wikidata, Apache Tika, TrID, File Formats Wiki, GitHub Linguist) и позволяет сравнить их покрытие. Полезен для быстрого поиска информации о форматах.

### File Formats Wiki (Just Solve the File Format Problem)

[File Formats Wiki](http://fileformats.archiveteam.org/wiki/Main_Page) — вики проекта Archive Team «Just Solve the File Format Problem», документирующая форматы файлов силами сообщества.

*   **Содержание**: Очень широкий спектр форматов, включая редкие и устаревшие
*   **Сообщество**: Открытое редактирование
*   **Использование**: Справочная информация о редких форматах, ссылки на спецификации и программы

### FileFormat.Info

[FileFormat.Info](https://www.fileformat.info/) — справочный сайт с описаниями форматов файлов и сведениями о символах Unicode. Не является вики и не связан с реестрами цифрового сохранения, но бывает полезен как быстрый справочник.

## Использование реестров

### Поиск информации о формате

1. Найдите формат в реестре
2. Изучите характеристики формата
3. Проверьте риски сохранения
4. Определите рекомендуемые действия

### Интеграция с инструментами

Многие инструменты используют реестры:

*   **Siegfried**: PRONOM (по умолчанию), а также MIME-info и LC FDD
*   **FIDO**: PRONOM
*   **DROID**: PRONOM

### Оценка рисков

Реестры помогают оценить риски форматов:

*   **Поддержка**: Насколько хорошо поддерживается формат
*   **Риски**: Какие риски существуют для сохранения
*   **Рекомендации**: Что делать с форматом

## Сравнение реестров

| Реестр | Источник | Специализация | Использование |
| :--- | :--- | :--- | :--- |
| **PRONOM** | Национальный архив Великобритании | Общие форматы, сигнатуры | **Для инструментов идентификации** |
| **LC FDD** | Библиотека Конгресса США | Устойчивость форматов | Для оценки устойчивости |
| **Wikidata** | Сообщество | Универсальный хаб | Для связывания идентификаторов |
| **Digipres.org** | Сообщество | Агрегация данных реестров | Для быстрого поиска |
| **File Formats Wiki** | Archive Team | Широкий спектр, редкие форматы | Для справочной информации |

## Рекомендации

### Выбор реестра

*   Используйте PRONOM для инструментов идентификации
*   Используйте LC FDD для оценки устойчивости форматов
*   Используйте Wikidata для связывания идентификаторов разных систем
*   Используйте File Formats Wiki для редких форматов

### Вклад в реестры

Можно внести вклад в реестры:

*   Добавление новых форматов (PRONOM принимает предложения новых сигнатур)
*   Улучшение документации
*   Исправление ошибок
*   Добавление примеров

### Рекомендации для Ruarxive

При описании цифровых коллекций в Ruarxive мы рекомендуем:
1.  Всегда проводить идентификацию форматов с помощью инструментов (Siegfried, DROID).
2.  Сохранять **PUID** (PRONOM ID), так как это наиболее точный идентификатор, вместе с версией сигнатурного файла.
3.  Сохранять **MIME-тип**, так как он широко используется в вебе, но помнить о его недостаточной детализации.
