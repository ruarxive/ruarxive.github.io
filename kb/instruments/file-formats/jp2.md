# JP2

**JP2 (JPEG 2000)** — формат изображений на основе вейвлет-преобразования, определённый в серии стандартов ISO/IEC 15444. Широко используется библиотеками и архивами для хранения оцифрованных материалов; описан в реестре форматов Библиотеки Конгресса США ([LC FDD — JPEG 2000 Part 1](https://www.loc.gov/preservation/digital/formats/fdd/fdd000143.shtml)).

## Зачем нужен JP2 вместо TIFF/JPEG

| Характеристика | JPEG | TIFF | JP2 |
| :--- | :--- | :--- | :--- |
| Сжатие с потерями | да | зависит от варианта | да |
| Сжатие без потерь | нет | да | да |
| Прогрессивная загрузка / несколько разрешений в файле | ограниченно | через пирамидальный TIFF | да |
| Большие изображения | плохо | да | да (через тайлы) |
| Метаданные (XMP, Exif) | да | да | да |
| Регион интереса (ROI) | нет | нет | да |
| Открытая спецификация | да | да | да |
| Поддержка браузерами | отличная | слабая | слабая |

Главные преимущества JP2 для архивов — сжатие без потерь, заметно уступающее по размеру несжатому TIFF, и возможность быстро получить из одного файла уменьшенную копию или фрагмент (это используют серверы [IIIF](/kb/instruments/file-formats/iiif)). Минусы — сложность формата и меньшее число зрелых реализаций по сравнению с TIFF.

## Части стандарта

| Часть | Что описывает | Расширение | PUID в PRONOM |
| :--- | :--- | :--- | :--- |
| **Part 1** (ISO/IEC 15444-1) | Базовая система кодирования и контейнер JP2 | `.jp2` | `x-fmt/392` |
| **Part 2** (ISO/IEC 15444-2) | Расширения, контейнер JPX | `.jpx` | `fmt/151` |
| **Part 3** (ISO/IEC 15444-3) | Motion JPEG 2000 (видео) | `.mj2` | `fmt/337` |
| **Part 6** (ISO/IEC 15444-6) | Составные изображения JPM (например, сканы документов со слоями) | `.jpm` | `fmt/463` |
| **Part 15** (ISO/IEC 15444-15) | **HTJ2K** (High-Throughput JPEG 2000) — быстрый блочный кодер, контейнер JPH | `.jph` | `fmt/1964` |

«Голый» кодовый поток без контейнера (`.j2c`, `.j2k`) в PRONOM имеет идентификатор `fmt/1794`. Идентификаторы сверены с сигнатурным файлом DROID V125.

Для архивных мастер-копий обычно выбирают **Part 1 (`.jp2`)** — его поддерживает наибольшее число программ.

## Структура файла

JP2 — это контейнер из «боксов» (box). Основные из них:

1. **JPEG 2000 Signature Box** — обязательная сигнатура в начале файла.
2. **File Type Box** — бренд и совместимость.
3. **JP2 Header Box** — заголовок изображения (размер, число компонент, разрядность) и описание цветового пространства.
4. **Contiguous Codestream Box** — собственно сжатые данные изображения.

Дополнительно файл может содержать XML-боксы и UUID-боксы (в них, например, хранятся метаданные XMP).

Если используются тайлы, изображение разбивается на независимо декодируемые блоки. Это позволяет открывать очень большие сканы на машинах с ограниченной памятью и отдавать фрагменты по запросу.

## Создание JP2

### Через OpenJPEG (открытый код)

[OpenJPEG](https://www.openjpeg.org/) — основная открытая эталонная реализация JPEG 2000.

```bash
# Установка
sudo apt install libopenjp2-tools   # Debian/Ubuntu
brew install openjpeg               # macOS

# Конвертация TIFF → JP2 без потерь (режим по умолчанию)
opj_compress -i input.tif -o output.jp2

# С потерями: степень сжатия 10:1, необратимое вейвлет-преобразование 9/7
opj_compress -i input.tif -o output.jp2 -r 10 -I

# Тайлы 1024×1024 для большого скана (без потерь)
opj_compress -i large-scan.tif -o tiled.jp2 -t 1024,1024
```

Важные параметры `opj_compress`:

- без `-r` и `-q` сжатие выполняется **без потерь**;
- `-r` — **степень сжатия** (`-r 10` — в 10 раз; `-r 90` — в 90 раз, с очень сильными потерями), а не «качество»;
- `-q` — целевое качество в дБ PSNR (несовместимо с `-r`);
- `-n` — число уровней разрешения (по умолчанию 6, допустимо от 1 до 33; `-n 0` вызывает ошибку);
- `-t` — размер тайла;
- `-I` — необратимое преобразование (только для сжатия с потерями).

> Команды проверены на OpenJPEG 2.5.4 (октябрь 2026): файл, сжатый без параметров, после `opj_decompress` попиксельно совпадает с исходным.

### Через ImageMagick

```bash
# ImageMagick использует OpenJPEG; параметры кодера ограничены
magick input.tif output.jp2
```

### Через libvips (быстро, для больших объёмов)

```bash
# libvips должен быть собран с поддержкой OpenJPEG
vips jp2ksave input.tif output.jp2 --lossless --tile-width 1024 --tile-height 1024
```

Параметры операции `jp2ksave` (`Q`, `lossless`, `tile_width`, `tile_height`, `subsample_mode`) описаны в [документации libvips](https://www.libvips.org/API/current/method.Image.jp2ksave.html).

### Через Grok

[Grok](https://github.com/GrokImageCompression/grok) — высокопроизводительный кодек JPEG 2000 на C++ с поддержкой HTJ2K. Предоставляет утилиты командной строки `grk_compress` и `grk_decompress`; их параметры описаны в руководстве (`man grk_compress`) в репозитории проекта.

## Валидация

### jpylyzer

[jpylyzer](https://jpylyzer.openpreservation.org/) — стандартный в цифровом сохранении валидатор и анализатор свойств JP2 (проект Open Preservation Foundation). Проверяет соответствие файла спецификации Part 1 и выводит его характеристики в XML.

```bash
pip install jpylyzer
jpylyzer output.jp2 > output.jp2.xml
# в отчёте ищите <isValid format="jp2">True</isValid>
```

> Проверено с jpylyzer 2.2.1 (октябрь 2026).

### Проверка декодирования

```bash
# opj_decompress — проверка возможности полного декодирования
opj_decompress -i output.jp2 -o /tmp/check.tif

# opj_dump — параметры кодового потока (тайлы, уровни разрешения и т. д.)
opj_dump -i output.jp2
```

### Метаданные и PUID

```bash
# Извлечение XMP и Exif
exiftool output.jp2

# Получение PUID через Siegfried
sf output.jp2
```

PUID в PRONOM для JP2 (Part 1): [`x-fmt/392`](https://www.nationalarchives.gov.uk/PRONOM/x-fmt/392).

## Сценарии использования

- **Сканы книг и периодики** — распространённый формат мастер-копий в проектах массовой оцифровки библиотек.
- **Сканы архивных документов** — крупноформатные материалы с использованием тайлов.
- **Снимки объектов культурного наследия** — фотографии, требующие высокого качества и хранения без потерь.
- **Карты и чертежи** — большие изображения, которые нужно просматривать фрагментами.

## Рекомендации

*   Для мастер-копий используйте сжатие **без потерь** (по умолчанию в `opj_compress`, `--lossless` в libvips).
*   Если нужно сжатие с потерями, задавайте умеренную степень сжатия и проверяйте результат визуально; сохраняйте параметры кодирования в метаданных.
*   Включайте **тайлы** для больших изображений — это ускоряет просмотр и доставку фрагментов.
*   Встраивайте **метаданные** (XMP: название, источник, дата, автор) при создании или сразу после.
*   Проверяйте каждый файл через **jpylyzer** и пробное декодирование `opj_decompress`.
