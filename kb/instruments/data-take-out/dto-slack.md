# Slack

Возможности экспорта из Slack зависят от вашего тарифного плана и
прав доступа (требуется роль **Workspace Owner/Admin**). Для
персональной выгрузки из чужих рабочих пространств инструмента нет —
нужно либо стать владельцем, либо договориться с владельцем о
регулярных бэкапах.

## Экспорт данных (Free / Pro)

1.  Перейдите на страницу **Workspace Settings** → **Import/Export Data**.
2.  Выберите вкладку **Export**.
3.  Выберите диапазон дат.
4.  Нажмите **Start Export**.

### Что включено

*   История сообщений из **публичных** каналов (JSON).
*   Ссылки на файлы (сами файлы **не скачиваются** в архиве, их нужно
  качать скриптами — см. ниже).

> [!WARNING]
> На бесплатных и Pro тарифах экспорт **не включает**:
> *   личные сообщения (DMs);
> *   закрытые (private) каналы;
> *   данные участников рабочего пространства.

## Корпоративный экспорт (Business+ / Enterprise Grid)

На тарифах Business+ и Enterprise Grid можно запросить
**Corporate Export**, который включает:

*   личные сообщения;
*   закрытые каналы;
*   файлы в виде вложений (не ссылок);
*   метаданные пользователей.

Для этого нужно подать заявку в поддержку Slack и подтвердить
юридическую необходимость. Подготовка занимает **от 1 до 30 дней** в
зависимости от размера workspace.

## Структура экспорта

Стандартный экспорт содержит:

```
slack-export/
├── channels.json              # Список каналов
├── integration_logs.json
├── users.json                 # Список пользователей
├── CHANNEL_NAME/
│   ├── 2024-01-15.json        # Сообщения по дням
│   ├── 2024-01-16.json
│   └── ...
└── ...
```

Каждое сообщение в JSON содержит: `type`, `user`, `text`, `ts`
(timestamp), `thread_ts` (если в треде), `files` (список вложений с
URL), `reactions`.

## Инструменты для скачивания файлов

Так как стандартный экспорт содержит только *ссылки* на файлы, для
полного бэкапа используйте сторонние инструменты:

*   [**slack-export-viewer**](https://github.com/hfaran/slack-export-viewer) —
  Python-скрипт, который скачивает файлы и поднимает локальный
  веб-просмотрщик экспорта.
*   [**slackdump**](https://github.com/rusq/slackdump) — утилита на Go,
  которая делает полный бэкап workspace за один проход, включая
  личные сообщения (если у вас есть права).
*   [**slack-archive**](https://github.com/cleverer/slack-archive) —
  Python-скрипт для регулярных инкрементальных бэкапов.

## Ограничения

*   **Workspace Owner/Admin** — для большинства операций экспорта.
*   **Файлы старше 90 дней** удаляются с серверов Slack (если
  включена опция «File retention policy»). Скачивайте регулярно.
*   **Реакции** на сообщения сохраняются, но **пользовательские
  эмодзи** могут быть потеряны, если не были загружены в архив.
*   **Интеграции** (Jira, GitHub, etc.) сохраняют только свои
  сообщения, но не данные из самих интеграций.

## Регулярные бэкапы

Для организаций, которым важно сохранять переписку на случай потери
доступа или юридических споров, рекомендуется:

1. Включить в Slack **Compliance Export** (доступен на Enterprise Grid).
2. Настроить передачу ежедневных дампов в S3/GCS.
3. Обернуть файлы в [WARC через metawarc](/kb/instruments/ruarxive-tools/metawarc)
  для индексации и поиска.
