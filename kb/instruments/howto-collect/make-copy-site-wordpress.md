# wparc — как создать цифровой архив сайта на WordPress

[**wparc**](https://github.com/ruarxive/wparc) — утилита командной строки Ruarxive для архивации данных сайтов на WordPress, на котором работает огромное число сайтов СМИ, организаций и личных блогов. Первая (бета) версия была представлена в [посте #32 от 31.03.2022](https://t.me/ruarxive/32); текущая версия на PyPI — 1.0.8.

Утилита использует стандартное **REST API** WordPress, доступное по адресу `/wp-json/`. Вместо обхода HTML-страниц она читает структурированные данные, поэтому выгрузка получается быстрее, чем у классических веб-краулеров, и сохраняет метаданные (даты, авторы, рубрики, теги).

Подробнее о структурах данных — в [документации WordPress REST API](https://developer.wordpress.org/rest-api/). Полное описание утилиты — на странице [wparc](/kb/instruments/ruarxive-tools/wparc).

## Когда использовать wparc

*   На сайте много записей и страниц, и нужны их тексты и метаданные в машиночитаемом виде.
*   Нужна **структура** контента (записи, страницы, рубрики, теги, комментарии), а не визуальное оформление.
*   Нужно быстро сохранить медиафайлы из библиотеки WordPress.

## Когда не подходит

*   Нужно сохранить вид страниц, JavaScript-интерфейс, ленивую подгрузку — используйте [Browsertrix](/kb/instruments/tools/browsertrix) или [wget](/kb/instruments/tools/wget) с `--warc-file`.
*   REST API на сайте отключён или закрыт авторизацией.

Часто полезно сочетать оба подхода: данные через wparc и WARC-копию страниц краулером.

## Команды

*   **`ping`** — проверить, что API доступен, и узнать число маршрутов.
*   **`analyze`** — найти маршруты API, которых нет в списке известных (например, от плагинов).
*   **`dump`** — выгрузить данные всех маршрутов API в файлы `.json` и `.jsonl` в каталог `<домен>/data/`.
*   **`getfiles`** — скачать все медиафайлы, перечисленные в `wp_v2_media.jsonl`, в каталог `<домен>/files/`.

В версии 1.0.9 из репозитория (на PyPI ещё не опубликована) добавлены `index` (SQLite-индекс выгрузки) и `warc` (упаковка JSON-выгрузки в WARC). Отдельной команды `pack` нет.

## Пример использования

```bash
# Установка
pip install wparc

# 1. Проверить, доступен ли API
wparc ping example.com

# 2. Выгрузить все данные API в example.com/data/
wparc dump example.com

# 3. Скачать медиафайлы в example.com/files/
wparc getfiles example.com
```

Домен указывается без `https://`. Для медленных сайтов помогут `--timeout`, `--page-size` и `--retry-count` у `dump`.

> Команды сверены с README и `--help` wparc 1.0.8 (октябрь 2026).

## Примеры сайтов на WordPress

В [посте #32](https://t.me/ruarxive/32) в качестве примеров упоминались, в частности, [duma-rad.ru](https://duma-rad.ru/) и [www.iephb.ru](https://www.iephb.ru/). В октябре 2026 года оба отдавали JSON по адресу `/wp-json/`.

Проверить любой сайт можно, открыв в браузере `https://адрес-сайта/wp-json/` или выполнив `wparc ping адрес-сайта`.

## Ограничения

*   Некоторые владельцы сайтов на WordPress закрывают `/wp-json/` для неавторизованных пользователей — из таких сайтов данные этим способом не получить.
*   У старых версий WordPress (до 4.7) точки `/wp-json/` нет.
*   Плагины безопасности могут ограничивать частоту запросов к API; в этом случае уменьшите `--page-size` и увеличьте `--retry-count`.
*   Ссылки на медиафайлы внутри текстов записей остаются исходными; локальные копии лежат в `<домен>/files/` с той же структурой путей.

## Что ещё было в планах

В анонсе 2022 года упоминались проверка сайта на возможность выгрузки (сейчас это делают `ping` и `analyze`), упаковка в Data Package для долгосрочного хранения и выгрузка без API по шаблонам CMS. Две последние возможности пока не реализованы.

Найденные ошибки сообщайте в [issues](https://github.com/ruarxive/wparc/issues) репозитория **wparc**. Если REST API закрыт логином, wparc его не откроет: страницы, которые видны вашей учётной записи в браузере, снимают по гайду [«Вход на сайт»](/kb/guides/authenticated-crawling).
